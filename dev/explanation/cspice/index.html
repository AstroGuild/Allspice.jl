Differences from CSPICE

The package keeps the names, the argument order, the units and the numerical results of CSPICE N0067. It departs from CSPICE where the C interface carries hidden state or output arguments, and this page lists each departure, so that a reader who knows CSPICE or SPICE.jl can port a program with no surprise.

Call conventions

CSPICEThis package
A name ends in _cThe name has no suffix: spkezr_c is spkezr
A call fills or changes an argumentA call that changes its argument has a name that ends in !, as Julia code does: wninsd!
Results come back through output argumentsA call returns its results, several of them as a tuple: state, lt = spkezr(...)
Vectors and matrices are C arraysResults are static arrays (SVector, SMatrix) of StaticArrays.jl; inputs can be any AbstractVector or AbstractMatrix
An error sets a flag that the program must testAn error throws a SpiceError, whose field kind is the short message of CSPICE as a symbol and whose field msg is the text; missing SPK data throw a subtype with the bodies and the epoch
A "found" flag tells that a lookup failedA lookup returns nothing (bodn2c for an unknown name); a call that must return a value throws (gdpool for a variable that is not loaded)
Indices count from 0Indices count from 1: the first interval of a window, the first plate of a DSK, the first row of an EK
A file handle is an integer, and several calls work on a hidden "current" fileA handle is an object (DAFHandle, DASHandle) that the caller passes to each call
Loaded kernels are one table for the whole processLoaded kernels belong to a SpiceContext; see Contexts and threads
Output strings need a length argumentA call returns a String
A cell or a window has a size that the caller declaresA Window grows as needed

The kind of an error is the short message of CSPICE in lower case where the same condition exists there, so SPICE(INVALIDDEGREE) becomes :invaliddegree.

No state between calls

CSPICE keeps buffers and saved search results between calls, for speed. This package keeps no such state: a query is a function of the loaded kernels and of its arguments. Three visible consequences follow.

  • Threads. Queries from many threads need no lock, and a kernel can be loaded while other threads query; see Contexts and threads.
  • Settings. The defaults of timdef, tsetyr and tparch, the tolerance of gfstol and the settings of dskstl belong to a context, not to the process.
  • Repeatable answers. Where the answer of CSPICE depends on an earlier call (for example ckgp directly after ckgpav on overlapping segments, the dates in a text kernel loaded after certain str2et calls, or the four padding bytes of each segment summary of a binary PCK, which CSPICE fills from the last SPK or CK summary it handled), this package returns the answer that CSPICE gives in a new process.

Numerical results

Each routine follows the arithmetic of its CSPICE counterpart, operation by operation, including the order of the terms of a sum; fused multiply-add is not used. For the same kernels and the same Float64 input, a result is equal to that of CSPICE bit for bit or differs by rounding; Coverage and validation says how this was checked and gives measured differences.

What is absent

The toolkit utilities that are programs (brief, mkspk, spkmerge and the others) are not part of the package. Coverage and validation lists the areas of the library that exist.
