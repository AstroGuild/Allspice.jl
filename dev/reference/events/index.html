Event searches and windows

The geometry finder is the set of searches of CSPICE, the gf routines, that return the window of epochs on which a geometric condition holds; a Window holds each result, and the calls of the second section combine windows. Sibling calls can throw different kinds for one condition, because each kind is the one of the CSPICE routine that the call ports; see SpiceError.

Searches

Allspice.gfdist — Function
gfdist([ctx,] target, abcorr, obsrvr, relate, refval, adjust, step, cnfine;
       tol=gfstol(ctx), bail=nothing, report=nothing, threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which the distance in km between target and obsrvr satisfies the relation relate with the reference value refval, as gfdist_c.

The result is a new Window that is a subset of the confinement window cnfine. cnfine is not modified, and an empty cnfine gives an empty window. CSPICE needs a result cell, a workspace and an interval count; this call needs none.

Arguments

  • target, obsrvr: names or IDs of two different bodies.
  • abcorr: any aberration correction of spkezr, a string or an Aberration.
  • relate: "<", "=", ">", "LOCMIN", "LOCMAX", "ABSMIN" or "ABSMAX", in any case. An inequality gives the intervals on which it holds. "=" and the extrema with adjust = 0 give intervals of zero length, one for each event. A local extremum is reported only if it is strictly inside an interval of cnfine; an absolute extremum can be at an end.
  • refval: reference value in the unit of the quantity. The extrema do not use it.
  • adjust: zero, except for "ABSMIN" and "ABSMAX". There a positive value gives the window on which the quantity is within adjust of the absolute extremum.
  • step: step of the search in seconds, positive. The search samples the direction of change of the quantity at this step to find its local extrema, so step must be shorter than the shortest interval, inside cnfine, on which the quantity is monotone. A longer step can miss events. A shorter step costs time and gives no accuracy: tol sets the accuracy.
  • cnfine: the Window to search in. For "=" the quantity is also evaluated up to 0.5 s outside each interval, so the kernels must cover that margin.

Keywords

Every search takes these keywords; gfevnt, gfocce and gffove take tol as an argument instead.

  • tol: convergence tolerance in seconds, positive. Each end point of the result is bisected until its bracket is not longer than tol. The default is the value of gfstol for the context.
  • bail: nothing, or a function without arguments that the search calls in its loops. When it returns true the search stops with an InterruptException.
  • report: nothing, or a progress callback (gfrepi, gfrepu, gfrepf of CSPICE). The search calls report(:init, window, prefix, suffix) at the start of a pass over window, report(:update, ivbeg, ivend, et) while it searches [ivbeg, ivend], and report(:final) at the end of the pass. prefix and suffix are the two strings of the progress message of CSPICE, such as "Distance pass 1 of 2" and "done.".
  • threads: if true, each interval that is searched runs in its own task. The result does not change. The callbacks, and the functions of gfuds and gfudb, are then called from several threads.

A search uses the kernels that are loaded when it starts. A furnsh or an unload on another thread does not change a search that runs, and several searches can run at the same time.

Throws SpiceError with the kind

  • :invalidstep if step <= 0, :invalidtolerance if tol <= 0;
  • :notrecognized if relate is not a relation;
  • :valueoutofrange if adjust < 0, :invalidvalue if adjust is not zero with a relation other than "ABSMIN" and "ABSMAX";
  • :idcodenotfound if a body name is not known, :bodiesnotdistinct if the two bodies are the same;
  • :invalidoption if abcorr is not a correction.

The errors of spkezr, such as missing ephemeris data, come from the epochs that the search samples.

Examples

The example needs a leap seconds kernel and an SPK with the Earth and the Moon.

furnsh("naif0012.tls")
furnsh("de440s.bsp")
cnfine = Window([str2et("2025 JAN 01"), str2et("2026 JAN 01")])

# Perigees of the Moon: local minima of the distance, searched with a step of one day.
perigees = gfdist("MOON", "NONE", "EARTH", "LOCMIN", 0.0, 0.0, 86400.0, cnfine)
for i in 1:wncard(perigees)
    et, _ = wnfetd(perigees, i)          # an event is an interval of zero length
    println(et2utc(et, "C", 0))
end

# Intervals on which the Moon is nearer than 370000 km, and their total length.
near = gfdist("MOON", "NONE", "EARTH", "<", 370000.0, 0.0, 86400.0, cnfine)
wnsumd(near)[1]                          # seconds

See also gfrr, gfsep, gfpa, gfposc, gfuds, gfstol, Window.

Allspice.gfsep — Function
gfsep([ctx,] targ1, shape1, frame1, targ2, shape2, frame2, abcorr, obsrvr, relate,
      refval, adjust, step, cnfine; tol=gfstol(ctx), bail=nothing, report=nothing,
      threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which the angular separation in radians of targ1 and targ2, as seen from obsrvr, satisfies the relation relate with refval, as gfsep_c.

Each shape is "POINT" or "SPHERE", in any case. For a sphere the separation is measured from the limb, so it is negative when the disks overlap. The radius of the sphere is the largest of the radii of the body (BODY<id>_RADII, km). frame1 and frame2 are not read, as in CSPICE; pass " ". The three bodies must differ. The other arguments, the keywords and the result are those of gfdist.

Throws the errors of gfdist, and SpiceError with the kind

  • :notrecognized if a shape is not one of the two;
  • the kinds of srfrec if the radii of a sphere are missing or not valid;
  • :insidebody or :badgeometry if the observer is not outside a sphere at an epoch of the search.

See also gfdist, gfoclt.

Allspice.gfposc — Function
gfposc([ctx,] target, frame, abcorr, obsrvr, crdsys, coord, relate, refval, adjust,
       step, cnfine; tol=gfstol(ctx), bail=nothing, report=nothing,
       threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which the coordinate coord of the position of target relative to obsrvr in the frame frame satisfies the relation relate with refval, as gfposc_c.

The coordinate systems and their coordinates, in any case, are

crdsyscoord
"RECTANGULAR""X", "Y", "Z"
"LATITUDINAL""RADIUS", "LONGITUDE", "LATITUDE"
"RA/DEC""RANGE", "RIGHT ASCENSION", "DECLINATION"
"SPHERICAL""RADIUS", "COLATITUDE", "LONGITUDE"
"CYLINDRICAL""RADIUS", "LONGITUDE", "Z"
"GEODETIC""LONGITUDE", "LATITUDE", "ALTITUDE"
"PLANETOGRAPHIC""LONGITUDE", "LATITUDE", "ALTITUDE"

Angles, and refval and adjust for an angle, are in radians; lengths are in km. Longitude is in (-pi, pi] in the latitudinal, spherical and geodetic systems. Longitude in the cylindrical and planetographic systems, and right ascension, are in [0, 2 pi). Longitude is positive east, except the planetographic one, which has the sense of recpgr for the center of frame (positive west for a prograde body such as Mars). The geodetic and planetographic systems use the radii of the center of frame, whose two equatorial radii must be equal.

A search on a longitude or on a right ascension accounts for the jump at the branch cut: the jump gives no root and no extremum. Such a search converges to max(1e-7, tol / 10) seconds, not to tol.

The other arguments, the keywords and the result are those of gfdist.

Throws the errors of gfdist, and SpiceError with the kind

  • :notsupported if the system or the coordinate is not in the table, or if the equatorial radii differ;
  • :unknownframe if frame is not known (:noframe with the geodetic and planetographic systems);
  • :badframe if, for these two systems, the center of frame has no radii loaded.

Examples

The example needs a leap seconds kernel and an SPK with the Earth and the Sun.

furnsh("naif0012.tls")
furnsh("de440s.bsp")
cnfine = Window([str2et("2025 JAN 01"), str2et("2026 JAN 01")])

# Epochs at which the Sun crosses the equator of J2000, with a step of 10 days.
w = gfposc("SUN", "J2000", "LT+S", "EARTH", "RA/DEC", "DECLINATION", "=", 0.0, 0.0,
    10 * 86400.0, cnfine)
[et2utc(wnfetd(w, i)[1], "C", 0) for i in 1:wncard(w)]

# Intervals on which the right ascension of the Sun is below 6 h (pi/2 rad).
gfposc("SUN", "J2000", "LT+S", "EARTH", "RA/DEC", "RIGHT ASCENSION", "<", pi / 2, 0.0,
    10 * 86400.0, cnfine)

See also gfdist, gfsubc, gfsntc.

gfrr([ctx,] target, abcorr, obsrvr, relate, refval, adjust, step, cnfine;
     tol=gfstol(ctx), bail=nothing, report=nothing, threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which the range rate in km/s of target relative to obsrvr satisfies the relation relate with refval, as gfrr_c.

The arguments, the keywords, the result and the errors are those of gfdist. The search also reads the state 1 s before and 1 s after each epoch that it samples, as CSPICE does, so the kernels must cover cnfine with that margin.

Allspice.gfpa — Function
gfpa([ctx,] target, illmn, abcorr, obsrvr, relate, refval, adjust, step, cnfine;

Allspice.gfuds — Function
gfuds([ctx,] udfuns, udqdec, relate, refval, adjust, step, cnfine;
      tol=gfstol(ctx), bail=nothing, report=nothing, threads=false) -> Window

Return the window of cnfine on which the scalar function udfuns(et) satisfies the relation relate with refval, as gfuds_c.

udfuns(et) returns a real number. udqdec(et) returns true if udfuns decreases at et, and must return a Bool. For a function without an analytical derivative, use et -> uddc(udfuns, et, dx). Each function takes the epoch alone. It must return the same value each time for the same epoch. CSPICE also passes udfuns to udqdec; here a closure does that. step must be shorter than the shortest interval, inside cnfine, on which udfuns is monotone. The other arguments, the keywords and the result are those of gfdist.

The search reads no kernel, and ctx only gives the default of tol. A kernel call in udfuns reads the kernels that are loaded at the time of that call, not those of the start of the search.

Throws SpiceError(:invalidstep) if step <= 0, SpiceError(:invalidtolerance) if tol <= 0, SpiceError(:notrecognized) if relate is not a relation, SpiceError(:valueoutofrange) if adjust < 0, and SpiceError(:invalidvalue) if adjust is not zero with a relation other than "ABSMIN" and "ABSMAX".

Examples

julia> cnfine = Window([0.0, 10.0]);

julia> w = gfuds(sin, et -> cos(et) < 0, ">", 0.5, 0.0, 1.0, cnfine);

julia> [round.(wnfetd(w, i); digits=4) for i in 1:wncard(w)]
2-element Vector{Tuple{Float64, Float64}}:
 (0.5236, 2.618)
 (6.8068, 8.9012)

julia> peaks = gfuds(sin, et -> uddc(sin, et, 1e-3), "LOCMAX", 0.0, 0.0, 1.0, cnfine);

julia> [round(wnfetd(peaks, i)[1]; digits=4) for i in 1:wncard(peaks)]
2-element Vector{Float64}:
 1.5708
 7.854

See also gfudb, uddc, uddf, gfdist.

Allspice.gfudb — Function
gfudb([ctx,] udfunb, step, cnfine; tol=gfstol(ctx), bail=nothing, report=nothing,
      threads=false) -> Window

Return the window of cnfine on which the boolean function udfunb(et) is true, as gfudb_c.

udfunb takes the epoch alone and must return a Bool; the scalar function that CSPICE passes through to it is not needed. The search samples udfunb from the start of each interval of cnfine in steps of step seconds, and bisects each change of value until the bracket is not longer than tol. step must therefore be shorter than the shortest interval on which udfunb keeps one value. The keywords are those of gfdist, and ctx acts as in gfuds.

Throws SpiceError(:invalidstep) if step <= 0 and SpiceError(:invalidtolerance) if tol <= 0.

Examples

julia> w = gfudb(et -> sin(et) > 0.5, 1.0, Window([0.0, 10.0]));

julia> [round.(wnfetd(w, i); digits=4) for i in 1:wncard(w)]
2-element Vector{Tuple{Float64, Float64}}:
 (0.5236, 2.618)
 (6.8068, 8.9012)

See also gfuds, gfoclt, gftfov.

Allspice.gfevnt — Function
gfevnt([ctx,] udstep, udrefn, gquant, qpnams, qcpars, qdpars, qipars, qlpars, op,
       refval, tol, adjust, cnfine; bail=nothing, report=nothing, threads=false) -> Window

Return the window of cnfine on which the quantity gquant satisfies the relation op with the reference value refval, as gfevnt_c. This is the general entry of the geometry finder, with a step and a refinement function that the caller supplies.

Arguments

  • udstep: the step in seconds, a positive number or a function et -> step. A step function that returns a value that is not positive throws SpiceError(:invalidstep) during the search.
  • udrefn: the refinement function (t1, t2, s1, s2) -> t, which picks the next epoch to test in a bracket [t1, t2] across which the condition changes. It returns an epoch in the bracket. s1 and s2 are the values (Bool) of the condition of the search at t1 and t2. gfrefn is the bisection of CSPICE.
  • gquant: "DISTANCE", "ANGULAR SEPARATION", "COORDINATE", "RANGE RATE", "PHASE ANGLE" or "ILLUMINATION ANGLE", in any case.
  • qpnams, qcpars: the names of the parameters of the quantity and their string values, in the same order. The parameters that each quantity needs are in the table below. A value is the string that the search of the quantity takes for that argument, for example ILLUM is the illmn of gfpa.
  • qdpars: the three numbers of the vector DVEC of a surface intercept, or of SPOINT of an illumination angle. The name DVEC or SPOINT is in qpnams with a blank string value. Another quantity reads no number: pass Float64[].
  • qipars, qlpars: not read; they keep the argument order of CSPICE. Pass Int[] and Bool[].
  • op, refval, adjust, cnfine: as relate, refval, adjust and cnfine of gfdist.
  • tol: convergence tolerance in seconds, positive. It is an argument, as in CSPICE; the default of gfstol is not used.
gquantParameters in qpnams
"DISTANCE", "RANGE RATE"TARGET, OBSERVER, ABCORR
"PHASE ANGLE"TARGET, OBSERVER, ILLUM, ABCORR
"ANGULAR SEPARATION"TARGET1, FRAME1, SHAPE1, TARGET2, FRAME2, SHAPE2, OBSERVER, ABCORR
"COORDINATE"TARGET, OBSERVER, ABCORR, COORDINATE SYSTEM, COORDINATE, REFERENCE FRAME, VECTOR DEFINITION, METHOD, DVEC, DREF
"ILLUMINATION ANGLE"TARGET, ILLUM, OBSERVER, ABCORR, REFERENCE FRAME, ANGTYP, METHOD, SPOINT

VECTOR DEFINITION is POSITION, SUB-OBSERVER POINT or SURFACE INTERCEPT POINT. Every parameter in the row of the quantity must be in qpnams, also one that the quantity does not use (a blank value is then enough). The keywords bail, report and threads are those of gfdist.

Throws SpiceError with the kind

  • :notrecognized if gquant or op is not known;
  • :invalidcount if there are more than 10 parameter names, fewer values in qcpars than names, or fewer than 3 values in qdpars where a vector is needed;
  • :missingvalue if a parameter of the quantity is not in qpnams;
  • :notsupported if the vector definition is not known.

Also throws the errors of the search for the quantity: gfdist, gfrr, gfpa, gfsep, gfposc, gfsubc, gfsntc, gfilum.

Examples

The example needs a leap seconds kernel and an SPK with the Earth and the Moon, loaded with furnsh.

cnfine = Window([str2et("2025 JAN 01"), str2et("2025 MAR 01")])

# The search of `gfdist("MOON", "LT+S", "EARTH", "<", 370000.0, 0.0, 86400.0, cnfine)`,
# with a tolerance of 1e-3 s.
gfevnt(86400.0, gfrefn, "DISTANCE", ["TARGET", "OBSERVER", "ABCORR"],
    ["MOON", "EARTH", "LT+S"], Float64[], Int[], Bool[], "<", 370000.0, 1e-3, 0.0, cnfine)

See also gfocce, gffove.

Allspice.gfstol — Function
gfstol([ctx,] value) -> Float64
gfstol([ctx]) -> Float64

Set the default convergence tolerance of the geometry finder searches on the context ctx to value seconds and return it, as gfstol_c. Without value, return the current default.

The default of a new context is 1.0e-6 s. The keyword tol of a search overrides it for that search. A search reads the default once, at its start, so a change does not reach a search that is running. kclear, furnsh and unload do not change it.

Throws SpiceError(:invalidtolerance) if value <= 0; the default is then unchanged.

Examples

julia> ctx = SpiceContext();

julia> gfstol(ctx)
1.0e-6

julia> gfstol(ctx, 1e-3)
0.001

julia> gfstol(ctx)
0.001

See also gfdist.

Allspice.gfrefn — Function
gfrefn(t1, t2, s1=false, s2=true) -> Float64

Return the midpoint of the bracket [t1, t2], as gfrefn_c. This is the default refinement function of the geometry finder.

The result is t1 * 0.5 + t2 * 0.5, clamped between t1 and t2; the two ends can be in either order. s1 and s2, the values of the search condition at the two ends, are not used.

See also gfevnt, gfocce, gffove.

Allspice.uddc — Function
uddc(udfunc, x, dx) -> Bool

Return true if the numerical derivative uddf(udfunc, x, dx) is negative, as uddc_c.

This is the "is decreasing" test that gfuds needs, for a function without an analytical derivative: pass et -> uddc(udfuns, et, dx) as udqdec.

Throws SpiceError(:dividebyzero) if dx == 0.

Examples

julia> uddc(cos, 1.0, 1e-3)
true

See also uddf, gfuds.

Allspice.uddf — Function
uddf(udfunc, x, dx) -> Float64

Return the numerical derivative of the scalar function udfunc at x, as uddf_c.

The result is the central difference (udfunc(x + dx) - udfunc(x - dx)) / (2 dx). Unlike CSPICE, udfunc takes the abscissa alone.

Throws SpiceError(:dividebyzero) if dx == 0.

Examples

julia> uddf(x -> x^2, 3.0, 0.5)
6.0

See also uddc, gfuds.

Allspice.gfsubc — Function
gfsubc([ctx,] target, fixref, method, abcorr, obsrvr, crdsys, coord, relate, refval,
       adjust, step, cnfine; tol=gfstol(ctx), bail=nothing, report=nothing,
       threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which the coordinate coord of the sub-observer point on target, as seen from obsrvr, satisfies the relation relate with refval, as gfsubc_c.

The point is the one of subpnt, in the body-fixed frame fixref, which must be centered on target. method is one of the older forms of subpnt, "Near point: ellipsoid" or "Intercept: ellipsoid"; case and blanks are ignored. As in CSPICE, no other spelling is accepted: "NEAR POINT/ELLIPSOID" and a DSK method throw.

The coordinate systems, the coordinates, their units and ranges, and the convergence of a longitude search are those of gfposc. The other arguments, the keywords and the result are those of gfdist.

Throws SpiceError(:invalidstep), SpiceError(:invalidtolerance), SpiceError(:notrecognized), SpiceError(:valueoutofrange) and SpiceError(:invalidvalue) as gfdist does, and

  • SpiceError(:idcodenotfound) if a body name is not known, and SpiceError(:bodiesnotdistinct) if the two bodies are the same;
  • SpiceError(:invalidoption) if abcorr is not a correction;
  • SpiceError(:notsupported) if the system or the coordinate is not known, if the equatorial radii differ (geodetic and planetographic systems), or if method is not one of the two. The method is checked at the first epoch that is searched, so an empty cnfine gives no error for it, as in CSPICE;
  • SpiceError(:noframe) if fixref is not known, SpiceError(:invalidframe) if it is not centered on target, and SpiceError(:badframe) if its center has no radii loaded;
  • the kinds :invalidcount and :badaxislength of srfrec if the radii are not valid;
  • SpiceError(:degeneratecase) if the velocity of the point is not defined at an epoch of the search.

The errors of subpnt, such as missing ephemeris data, come from the epochs that the search samples.

Examples

The example needs a leap seconds kernel, an SPK, and a PCK with the radii and the orientation of Mars, loaded with furnsh.

cnfine = Window([str2et("2025 JAN 01"), str2et("2025 JAN 03")])

# Epochs at which the sub-Earth point on Mars crosses the prime meridian.
gfsubc("MARS", "IAU_MARS", "Near point: ellipsoid", "LT+S", "EARTH", "GEODETIC",
    "LONGITUDE", "=", 0.0, 0.0, 6 * 3600.0, cnfine)

See also gfsntc, gfposc, subpnt.

Allspice.gfsntc — Function
gfsntc([ctx,] target, fixref, method, abcorr, obsrvr, dref, dvec, crdsys, coord,
       relate, refval, adjust, step, cnfine; tol=gfstol(ctx), bail=nothing,
       report=nothing, threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which the coordinate coord of a surface intercept point on target satisfies the relation relate with refval, as gfsntc_c. The point is where the ray from obsrvr along dvec meets the reference ellipsoid of target.

dvec is a vector of 3 elements in the frame dref. The point is the one of sincpt, in the body-fixed frame fixref, which must be centered on target. method must be "Ellipsoid"; case and blanks are ignored. As in CSPICE, no DSK shape is accepted.

The search is confined to the epochs at which the ray meets the target. A first pass with the step step finds the window on which the intercept exists, and each interval of that window is then made shorter by tol + 1 seconds at both ends. The result is a subset of that shortened window. step must therefore also be shorter than the shortest interval on which the intercept exists, and than the shortest gap between two such intervals.

The coordinate systems, the coordinates, their units and ranges, and the convergence of a longitude search are those of gfposc. The other arguments, the keywords and the result are those of gfdist.

Throws the errors of gfsubc, with "Ellipsoid" as the only method, and SpiceError(:badarg) if dvec does not have 3 elements, SpiceError(:zerovector) if dvec is zero, and SpiceError(:noframe) if dref is not known.

See also gfsubc, gfposc, sincpt.

Allspice.gfilum — Function
gfilum([ctx,] method, angtyp, target, illmn, fixref, abcorr, obsrvr, spoint, relate,
       refval, adjust, step, cnfine; tol=gfstol(ctx), bail=nothing, report=nothing,
       threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which an illumination angle in radians at the surface point spoint of target satisfies the relation relate with refval, as gfilum_c. The angle is the one of illumg.

Arguments

  • method: must be "ELLIPSOID", in any case. The surface normal is the one of the reference ellipsoid.
  • angtyp: "PHASE" (the angle at the point between the directions to the source illmn and to the observer obsrvr), "INCIDENCE" (between the normal and the direction to the source) or "EMISSION" (between the normal and the direction to the observer). Case and blanks are ignored.
  • target, illmn, obsrvr: body names or IDs. The target must differ from the other two; the source can be the observer.
  • fixref: body-fixed frame of spoint. It must be centered on target.
  • abcorr: "NONE" or a reception correction.
  • spoint: a vector of 3 elements in km. It is taken as a point of the surface without a check.

The other arguments, the keywords and the result are those of gfdist.

Throws SpiceError(:invalidstep), SpiceError(:invalidtolerance), SpiceError(:notrecognized), SpiceError(:valueoutofrange) and SpiceError(:invalidvalue) as gfdist does, and

  • SpiceError(:idcodenotfound) if a body name is not known, and SpiceError(:bodiesnotdistinct) if the target is the observer or the source;
  • SpiceError(:invalidoption) if abcorr is not a correction, and SpiceError(:notsupported) if it is a transmission correction;
  • SpiceError(:badarg) if spoint does not have 3 elements;
  • SpiceError(:invalidmethod) if method is not "ELLIPSOID";
  • SpiceError(:unknownframe) if fixref is not known, and SpiceError(:invalidframe) if it is not centered on target;
  • SpiceError(:notsupported) if angtyp is not one of the three.

Also throws the kinds of srfrec if the radii of target are missing or not valid. The errors of spkcpt and spkcpo come from the epochs that the search samples.

See also ilumin, illumg, gfpa.

Allspice.gfoclt — Function
gfoclt([ctx,] occtyp, front, fshape, fframe, back, bshape, bframe, abcorr, obsrvr,
       step, cnfine; tol=gfstol(ctx), bail=nothing, report=nothing,
       threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which the body front occults the body back as seen from obsrvr, as gfoclt_c. A transit of front across back is the same event.

The result is a new Window that is a subset of the confinement window cnfine; cnfine is not modified. The test at each epoch is the one of occult.

Arguments

  • occtyp: "FULL" (the back target is hidden), "ANNULAR" (the front target lies wholly within the disk of the back target), "PARTIAL" (the disks overlap in part) or "ANY" (one of the three), in any case. With a point target only "ANY" is valid.
  • front, back, obsrvr: names or IDs of three different bodies.
  • fshape, bshape: "ELLIPSOID", "POINT" or "DSK/UNPRIORITIZED[/SURFACES = <list>]". At least one target must be extended, and a target with a DSK shape needs a point as the other target.
  • fframe, bframe: body-fixed frames of the extended targets. The frame of a point target is not read; a blank string is enough.
  • abcorr: "NONE" or a light time correction. Stellar aberration is not applied, as in CSPICE: "LT+S" acts as "LT".
  • step: step of the search in seconds, positive. The search samples the occultation state from the start of each interval of cnfine at this step, so step must be shorter than the shortest occultation of the type asked for, and than the shortest gap between two of them. Each change of state is then bisected until the bracket is not longer than tol.

The keywords are those of gfdist. A DSK shape uses the tolerances that dskstl set on the context. An observer on the surface of a target, such as a ground station under front = "EARTH", gives :notdisjoint or a wrong window; for the rising and setting of a body, search the elevation of azlcpo with gfuds.

Throws SpiceError(:invalidstep) if step <= 0, SpiceError(:invalidtolerance) if tol <= 0, and

  • SpiceError(:invalidshapecombo) if both shapes are "POINT", or if one shape is DSK and the other is not a point;
  • SpiceError(:idcodenotfound) if a body name is not known, and SpiceError(:bodiesnotdistinct) if two of the three bodies are the same;
  • SpiceError(:invalidshape) if a shape is not one of the three;
  • SpiceError(:invalidocctype) if occtyp is not known, and SpiceError(:badtypeshapecombo) if it is not "ANY" with a point target;
  • SpiceError(:invalidoption) if abcorr is not a correction;
  • SpiceError(:invalidframe) if the frame of an extended target is not known or not centered on it;
  • SpiceError(:notdisjoint) if, at an epoch of the search, the observer is inside a target or the targets overlap.

Also throws the kinds of srfrec if the radii of an ellipsoid are missing or not valid, and the kinds of occult for a DSK shape. The errors of spkpos and sincpt come from the epochs that the search samples.

Examples

The example needs a leap seconds kernel, an SPK, and a PCK with the radii and the orientation of the Sun and the Moon, loaded with furnsh.

cnfine = Window([str2et("2025 JAN 01"), str2et("2026 JAN 01")])

# Solar eclipses of 2025 as seen from the center of the Earth, with a step of 3 minutes.
w = gfoclt("ANY", "MOON", "ELLIPSOID", "IAU_MOON", "SUN", "ELLIPSOID", "IAU_SUN", "LT",
    "EARTH", 180.0, cnfine)
for i in 1:wncard(w)
    start, stop = wnfetd(w, i)
    println(et2utc(start, "C", 0), " to ", et2utc(stop, "C", 0))
end

See also gfocce, occult, gfdist.

Allspice.gftfov — Function
gftfov([ctx,] inst, target, tshape, tframe, abcorr, obsrvr, step, cnfine;
       tol=gfstol(ctx), bail=nothing, report=nothing, threads=false) -> Window

Return the window of epochs, in seconds past J2000 TDB, on which the body target is in the field of view of the instrument inst, as seen from obsrvr, as gftfov_c.

The result is a new Window that is a subset of the confinement window cnfine; cnfine is not modified. The test at each epoch is the one of fovtrg.

Arguments

  • inst: name or ID of an instrument whose field of view is in the kernel pool (see getfov). The instrument frame is evaluated at the epoch under test, as in fovtrg.
  • tshape: "ELLIPSOID" or "POINT", in any case. For an ellipsoid, any part of the reference ellipsoid in the field of view counts.
  • tframe: body-fixed frame of an ellipsoid, centered on target. It is not read for a point.
  • abcorr: any aberration correction of spkezr.
  • step: step of the search in seconds, positive. The search samples the visibility from the start of each interval of cnfine at this step, so step must be shorter than the shortest interval on which the target is visible, and than the shortest gap between two such intervals. Each change is then bisected until the bracket is not longer than tol.

The keywords are those of gfdist.

Throws SpiceError(:invalidstep) if step <= 0, SpiceError(:invalidtolerance) if tol <= 0, and

  • SpiceError(:invalidoption) if tshape is "RAY" (use gfrfov) or abcorr is not a correction;
  • SpiceError(:invalidshape) if tshape is not known;
  • SpiceError(:idcodenotfound) if the observer, the target or the instrument is not known, and SpiceError(:bodiesnotdistinct) if the target is the observer;
  • SpiceError(:invalidframe) if tframe is blank, not known or not centered on the target, and SpiceError(:frameinfonotfound) if the frame has no data (ellipsoid only);
  • SpiceError(:fovtoowide) if the angular radius of the field of view about its axis is not below 90 degrees minus 1e-6 rad;
  • SpiceError(:unknownframe) if the frame of the instrument is not known. This check is made at the first epoch that is searched.

Also throws the kinds of srfrec if the radii of an ellipsoid are missing or not valid, the errors of getfov, and the kinds of fovtrg for the shape of the field of view and for an observer inside the target. The errors of spkpos come from the epochs that the search samples.

See also gfrfov, gffove, fovtrg.

Windows

Allspice.Window — Type
Window()
Window(endpoints)

A set of disjoint closed intervals of the real line. It takes the place of the double-precision window cell of CSPICE.

Window() is empty. Window(endpoints) takes the pairs left₁, right₁, left₂, right₂, …. The pairs can be in any order and can overlap; they are sorted and merged, as wnvald! does. endpoints is copied.

A Window is an AbstractVector{Float64} of its endpoints in increasing order, so w[k], length(w) and iteration work. The field data holds the endpoints. A window has no size limit, so the CSPICE error SPICE(WINDOWEXCESS) cannot occur. A Window is not safe for concurrent mutation.

Throws SpiceError(:unmatchendpts) if the number of endpoints is odd, and SpiceError(:badendpoints) if a pair has left > right.

Examples

julia> w = Window([1, 3, 7, 11, 2, 5])
4-element Window:
  1.0
  5.0
  7.0
 11.0

julia> wncard(w)
2

See also wninsd!, wnunid, wnfetd, wnsumd.
