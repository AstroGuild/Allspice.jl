Kernels, contexts and the kernel pool

Contexts and errors

Allspice.SpiceContext — Type
SpiceContext()

Create an empty kernel context: the loaded kernels and the settings that the queries read.

Every call that reads kernels takes a context as an optional first argument. Without it the call uses default_context, one context for the whole process. Contexts are independent: furnsh on one context does not change another.

A context holds:

  • the loaded kernels and the kernel pool (furnsh, unload, kclear, pdpool, boddef);
  • the time defaults of timdef, tsetyr and tparch;
  • the pool watchers of swpool;
  • the DSK tolerances of dskstl and the search tolerance of gfstol.

A context can be shared between threads. A query takes no lock. A call that changes the context (a load, an unload, an edit of the pool or of a setting, a cvpool that clears an update) is atomic: a query that runs at the same time sees the context before the change or after it, never a part of it. Two changes on two threads are applied one after the other.

Examples

julia> ctx = SpiceContext();

julia> ktotal(ctx)
0

julia> pdpool(ctx, "MY_VALUES", [1.0, 2.0]);

julia> gdpool(ctx, "MY_VALUES")
2-element Vector{Float64}:
 1.0
 2.0

julia> expool("MY_VALUES")    # the default context is not changed
false

See also default_context, furnsh.

Allspice.SpiceError — Type
SpiceError <: Exception
SpiceError(kind::Symbol, msg) -> SpiceKindError

The abstract type of the exceptions that the package throws for a call that fails. Its subtypes are SpiceKindError, which most failures throw, and SpkInsufficientDataError, which a state query throws for missing SPK data.

Every subtype has the fields kind and msg. kind is a short symbol that names the failure, such as :spkinsuffdata, :kernelvarnotfound or :badarg; test it to handle one failure. msg is the text for a person. The constructor returns a SpiceKindError. In the docstrings, SpiceError(:x) means a SpiceError of either subtype whose kind is :x.

A kind is the short error message of the CSPICE routine that the call ports, in lower case (:kernelvarnotfound for SPICE(KERNELVARNOTFOUND)). Sibling calls can therefore report one failure with different kinds, as in CSPICE: a file that does not exist is :nosuchfile in furnsh and :filenotfound in spkobj, a bad correction is :invalidoption in spkezr and :spkinvalidoption in spkpos, and an unknown body name is :idcodenotfound in spkezr and :notranslation in bodvrd. Test the kinds that the docstring of the call lists. Where CSPICE has no message, because the failure cannot occur in C or the call has no counterpart, the kind is a name of this package; the main one is :badarg, for an argument of the wrong size or type.

A call of CSPICE that has a found flag returns nothing here when nothing is found, unless its docstring names another result (an error, 0, an empty string or vector, or the flag itself).

Allspice.ERROR_KINDS lists every kind. A kind that is not in the list cannot be constructed.

Examples

julia> try
           gdpool(SpiceContext(), "NO_SUCH_VARIABLE")
       catch err
           err isa SpiceError ? err.kind : rethrow()
       end
:kernelvarnotfound

See also SpkInsufficientDataError.

Allspice.SpkInsufficientDataError — Type
SpkInsufficientDataError <: SpiceError

The SpiceError of a state query that the loaded SPK data cannot answer.

spkezr and every call that reads the SPK segments of the loaded kernels throw it.

FieldMeaning
kind:spkinsuffdata, or :noloadedfiles if no SPK file is loaded
msgtext for a person; it lists the coverage of body
target, observerNAIF ID codes of the two bodies of the query
etepoch of the missing data, seconds past J2000 TDB
bodyID code of the body whose data are missing, or nothing if it is not known
loadedtrue if the loaded files hold body at other epochs than et

loaded tells an epoch outside the data (true) from a body that is in no loaded file (false). With an aberration correction, et is the epoch of the lookup that failed, which differs from the epoch of the call by the light time. body is nothing with no SPK file loaded. The ephemeris tables throw a SpiceKindError with the kind :spkinsuffdata for an epoch outside the table.

Examples

julia> err = try
           spkezr(SpiceContext(), 301, 0.0, "J2000", "NONE", 399)
       catch e
           e
       end;

julia> err isa SpkInsufficientDataError
true

julia> (err.kind, err.target, err.observer, err.et, err.body)
(:noloadedfiles, 301, 399, 0.0, nothing)

Allspice.ERROR_KINDS — Constant
Allspice.ERROR_KINDS

The kinds of SpiceError that the package can throw, as a sorted tuple of symbols.

Use it to check a kind that a handler tests: :spkinsuffdata in Allspice.ERROR_KINDS. A SpiceError with a kind that is not in the tuple cannot be constructed, so a comparison with such a kind is never true.

Loading and inspecting kernels

Allspice.furnsh — Function
furnsh([ctx,] path) -> Nothing

Load the kernel file at path into ctx, as furnsh_c.

The type is read from the file: SPK, binary PCK, CK, DSK, EK, text kernel or meta-kernel. A meta-kernel loads the files of its KERNELS_TO_LOAD list in order, with PATH_SYMBOLS and PATH_VALUES applied as in CSPICE. Without ctx the kernel goes into default_context.

  • A load that fails leaves ctx unchanged.
  • A later kernel has priority over an earlier one, as in CSPICE.
  • A path that is already loaded gets a second entry, as in CSPICE.
  • Direct edits of the kernel pool (pdpool, lmpool, ...) stay; the assignments of a text kernel are applied on top of them.
  • An SPK, PCK or CK file in the non-native byte order is read; it is converted in memory.

Throws SpiceError(:emptystring) if path is empty, SpiceError(:blankfilename) if it holds only blanks, SpiceError(:nosuchfile) if the file (or a file that a meta-kernel lists) does not exist, and SpiceError(:recursiveloading) if a meta-kernel lists a meta-kernel. A binary file that is damaged throws SpiceError(:baddaf), and a meta-kernel that is not consistent throws SpiceError(:badkernel).

Examples

furnsh("naif0012.tls")      # leap seconds
furnsh("de440s.bsp")        # planetary ephemeris
et = str2et("2025-03-01T12:00:00")
state, lt = spkezr("MOON", et, "J2000", "LT+S", "EARTH")

ctx = SpiceContext()        # a second, independent kernel set
furnsh(ctx, "mission.tm")

See also unload, kclear, ktotal, kdata.

source
Allspice.unload — Function
unload([ctx,] path) -> Nothing

Remove the kernel that was loaded from path out of ctx, as unload_c.

path is compared as a string with the file of kdata: the path given to furnsh, or for a file of a meta-kernel its KERNELS_TO_LOAD entry after the PATH_SYMBOLS substitution. Such a file can be unloaded alone; the meta-kernel stays loaded. If the path was loaded more than once, the last entry is removed, as in CSPICE; kinfo reports the first. A meta-kernel takes the files that it loaded with it. A path that is not loaded changes nothing, as in CSPICE.

If a text kernel is removed, the kernel pool is built again from the text kernels that stay, so direct edits of the pool (pdpool, ...) are lost, as in CSPICE. The kernels that stay are not read from disk again.

A binary kernel stays memory-mapped after the call until the garbage collector frees every snapshot that holds it (the value of Allspice.kernelset(ctx), which a query reads once). On Windows the file cannot be deleted or replaced while it is mapped; GC.gc() removes the map when no task refers to such a snapshot.

Throws SpiceError(:emptystring) if path is empty.

See also kclear.

source
Allspice.kclear — Function
kclear([ctx]) -> Nothing

Unload every kernel of ctx and empty its kernel pool, as kclear_c.

Direct edits of the pool are removed and the pool watchers are told of the change. The names of boddef stay, as in CSPICE. The time defaults of timdef are not reset. A binary kernel stays memory-mapped until the garbage collector frees the snapshots that hold it, as after unload.

Examples

julia> ctx = SpiceContext();

julia> pdpool(ctx, "A", [1.0]);

julia> kclear(ctx)

julia> expool(ctx, "A")
false

See also unload.

Allspice.ktotal — Function
ktotal([ctx,] kind="ALL") -> Int

Return the number of loaded kernels of the types in kind, as ktotal_c.

kind is "ALL" or a blank-separated list of SPK, CK, PCK, DSK, EK, TEXT and META, in any letter case. A meta-kernel counts once as META, and each file that it lists counts once. A path that is loaded twice counts twice. A word that is not a kernel type selects nothing.

Examples

julia> ktotal(SpiceContext())
0

See also kdata, kinfo.

Allspice.kinfo — Function
kinfo([ctx,] file) -> Union{Nothing,Tuple{String,String,Int}}

Return (filtyp, source, handle) of the loaded kernel with the path file, as kinfo_c, or nothing if the file is not loaded.

file is compared as a string with the path given to furnsh, as in CSPICE. If the path is loaded more than once, the first entry is reported. The elements have the meaning that they have in kdata; handle is always 0.

Throws SpiceError(:emptystring) if file is empty.

source
Allspice.kdata — Function
kdata([ctx,] which, kind="ALL") -> Union{Nothing,Tuple{String,String,String,Int}}

Return (file, filtyp, source, handle) of loaded kernel number which among the kernels of the types in kind, as kdata_c, or nothing if there is no such kernel.

which counts from 1 in load order, as in SPICE.jl; CSPICE counts from 0. kind is as for ktotal. file is the path given to furnsh, or for a file of a meta-kernel its KERNELS_TO_LOAD entry after the PATH_SYMBOLS substitution. filtyp is one of the type words of ktotal, and source is the meta-kernel that loaded the file, or "". handle is always 0, because a loaded kernel has no file handle in this package; it is kept for the tuple of CSPICE. nothing takes the place of the found flag of CSPICE.

Examples

for i in 1:ktotal("SPK")
    file, filtyp, source, _ = kdata(i, "SPK")
    println(file)
end

See also kinfo.

Allspice.spkcov — Function
spkcov(path, idcode) -> Window

Return the coverage Window of the body idcode in the SPK file path, as spkcov_c.

The window is the union of the intervals [start, stop] of the segments of that body, in seconds past J2000 TDB, as sorted disjoint intervals. collect(w) gives the endpoints as a Vector{Float64}. The window is empty if the body has no data. The file is read from disk and need not be loaded.

Reading the kernel pool

Allspice.gdpool — Function
gdpool([ctx,] name) -> Vector{Float64}

Return the numeric values of the kernel-pool variable name, as gdpool_c.

The result is a new vector with every value of the variable. Different from CSPICE, the call has no start and room arguments and no found flag: an absent variable is an error. Use expool or dtpool to test first. Blanks around name are ignored; letter case is significant.

Throws SpiceError(:kernelvarnotfound) if the variable is not in the pool and SpiceError(:typemismatch) if it holds character values.

Examples

julia> ctx = SpiceContext();

julia> pdpool(ctx, "BODY399_RADII", [6378.1366, 6378.1366, 6356.7519]);

julia> gdpool(ctx, "BODY399_RADII")
3-element Vector{Float64}:
 6378.1366
 6378.1366
 6356.7519

See also gipool, gcpool, bodvrd, pdpool.

Allspice.bodvrd — Function
bodvrd([ctx,] body, item) -> Vector{Float64}

Return the values of the kernel-pool variable BODY<id>_<item> for body, as bodvrd_c.

body is a body name, a string that holds an integer ("399") or an integer NAIF ID code. item is case sensitive, as in CSPICE; blanks around it are ignored. The values have the units of the kernel: km for "RADII", km^3/s^2 for "GM" in the NAIF kernels. There is no maxn argument.

Allspice.gnpool — Function
gnpool([ctx,] name, start=1, room=typemax(Int)) -> Vector{String}

Return the names of the kernel-pool variables that match the template name, as gnpool_c.

In the template * stands for any substring and % for any one character; letter case is ignored. The result holds at most room names, from match number start. start counts from 1, as in SPICE.jl; CSPICE counts from 0. The matches are in ascending order of the name; CSPICE returns them in the order of its hash table. The result is empty if nothing matches; there is no found flag.

Throws SpiceError(:badarraysize) if room < 1.

Examples

julia> ctx = SpiceContext();

julia> pdpool(ctx, "BODY399_GM", [398600.4]); pdpool(ctx, "BODY301_GM", [4902.8]);

julia> gnpool(ctx, "BODY%%%_GM")
2-element Vector{String}:
 "BODY301_GM"
 "BODY399_GM"

Allspice.szpool — Function
szpool(name) -> Union{Int,Nothing}

Return the kernel-pool size parameter name of CSPICE N0067, or nothing if the name is not one, as szpool_c.

The names are MAXVAR, MAXVAL, MAXLIN, MAXCHR, MXNOTE, MAXLEN and MAXAGT; letter case and blanks are ignored. Allspice.stpool — Function
stpool([ctx,] item, nth, contin) -> Union{String,Nothing}

Return string number nth of the character kernel-pool variable item, with continued elements joined, as stpool_c.

An element that ends with the continuation marker contin is joined with the next element; the marker is removed and the text before it is kept. nth counts the joined strings from 1, as in SPICE.jl; CSPICE counts from 0. Allspice.badkpv — Function
badkpv([ctx,] caller, name, comp, size, divby, type) -> Bool

Check the number of values and the type of the kernel-pool variable name, as badkpv_c, and return false if they are as expected.

The number of values n must satisfy n comp size, where comp is one of the operators of CSPICE, "=", "<", ">", "<=" and "=>" (not ">=" or "=<"); trailing blanks of comp are ignored. n must also be a multiple of divby; divby = 0 fails for every variable, as in CSPICE. type is 'N' for numbers or 'C' for strings; letter case is ignored. caller is the name that starts the error messages. Blanks around name are ignored, as in dtpool; CSPICE ignores only the trailing ones.

CSPICE signals an error and returns true for a bad variable; this call throws, so the result is always false.

Throws SpiceError:

  • :emptystring if caller, name or comp is empty;
  • :variablenotfound if the variable is not in the pool;
  • :unknowncompare if comp is not one of the above;
  • :badvariablesize if the number of values fails the comparison or is not a multiple of divby;
  • :badvariabletype if the variable has the other type;
  • :invalidtype if type is not 'N' or 'C'.

Examples

julia> ctx = SpiceContext();

julia> pdpool(ctx, "BODY399_RADII", [6378.1366, 6378.1366, 6356.7519]);

julia> badkpv(ctx, "MYPROG", "BODY399_RADII", "=", 3, 1, 'N')
false

julia> try
           badkpv(ctx, "MYPROG", "BODY399_RADII", "=>", 6, 1, 'N')
       catch err
           err.kind
       end
:badvariablesize

Changing the kernel pool

Allspice.pdpool — Function
pdpool([ctx,] name, values) -> Nothing

Set the kernel-pool variable name to the numbers values, as pdpool_c.

A variable of that name is replaced, whatever its type. An empty values changes nothing, as in CSPICE. Blanks around name are ignored.

Every table that is built from the pool (body names, frames, clocks) follows the edit. The edit stays through a later furnsh and through the unload of a binary kernel. It is lost at kclear and at the unload of a text kernel or a meta-kernel, as in CSPICE.

Throws SpiceError(:badvarname) if name is blank or longer than 32 characters.

Examples

julia> ctx = SpiceContext();

julia> pdpool(ctx, "BODY999_GM", [42.0]);

julia> gdpool(ctx, "BODY999_GM")
1-element Vector{Float64}:
 42.0

See also pipool, pcpool, dvpool, lmpool.

Allspice.lmpool — Function
lmpool([ctx,] cvals) -> Nothing

Load the text lines cvals into the kernel pool as the data section of a text kernel, as lmpool_c.

Each line holds text-kernel assignments (NAME = value, NAME += value); an assignment can continue on the next line. The lines start in a data section, and \begintext and \begindata work as in a file. The variables are direct edits of the pool, with the rules of pdpool.

Throws SpiceError(:badkernel) if an assignment is malformed; the pool is then unchanged.

Examples

julia> ctx = SpiceContext();

julia> lmpool(ctx, ["A = 1.5", "B = ( 'x', 'y' )"]);

julia> gdpool(ctx, "A"), gcpool(ctx, "B")
([1.5], ["x", "y"])

See also ldpool, furnsh.

source
Allspice.ldpool — Function
ldpool([ctx,] fname) -> Nothing

Load the variables of the text kernel file fname into the kernel pool, as ldpool_c.

Different from furnsh, the file does not enter the list of loaded kernels: ktotal does not count it and unload cannot remove it. Its variables are direct edits of the pool, with the rules of pdpool. A KERNELS_TO_LOAD list in the file is not followed.

Throws SpiceError(:emptystring) if fname is empty, SpiceError(:fileopenfailed) if the file does not exist and SpiceError(:badkernel) if an assignment is malformed.

source
Allspice.clpool — Function
clpool([ctx]) -> Nothing

Remove every variable from the kernel pool, as clpool_c.

The loaded kernels are not changed: binary kernels stay usable, and the text kernels stay in the list of ktotal although their variables are gone. A later unload of a text kernel builds the pool again from the text kernels that stay loaded.

See also kclear.

source
Allspice.swpool — Function
swpool([ctx,] agent, names) -> Nothing

Watch the kernel-pool variables names for the agent agent, as swpool_c. An agent is a name that the caller chooses for one watcher.

After this call, and after every later change of one of the variables, cvpool returns true once for agent. The names are added to the ones that the agent watches already. A watch belongs to one context: CSPICE keeps one table for the process, and here two contexts do not see the watches of each other.

Examples

julia> ctx = SpiceContext();

julia> swpool(ctx, "MY_AGENT", ["BODY399_GM"]);

julia> cvpool(ctx, "MY_AGENT"), cvpool(ctx, "MY_AGENT")
(true, false)

julia> pdpool(ctx, "BODY399_GM", [398600.4]);

julia> cvpool(ctx, "MY_AGENT")
true

See also poolversion.

Allspice.cvpool — Function
cvpool([ctx,] agent) -> Bool

Return true if a variable that agent watches changed since the last call for that agent, or since swpool, as cvpool_c.

The call clears the pending update. A change is an assignment by furnsh, ldpool, lmpool, pdpool, pcpool or pipool, or a deletion by dvpool. clpool, kclear and the unload of a text kernel count as a change of every watched variable, as in CSPICE. An agent without a watch gives false.

Allspice.poolversion — Function
poolversion([ctx]) -> Int

Return the number of changes of the kernel pool of ctx since the context was made. This call has no CSPICE counterpart.

Keep the value and compare it later to find out whether the pool changed. The call takes no lock; cvpool takes the lock of the context, because it clears the pending update. A change of the load list that assigns no variable (a binary kernel) does not count.

Examples

julia> ctx = SpiceContext();

julia> v = poolversion(ctx);

julia> pdpool(ctx, "A", [1.0]);

julia> poolversion(ctx) - v
1

See also swpool, cvpool.

Allspice.bods2c — Function
bods2c([ctx,] name) -> Union{Int,Nothing}

Return the NAIF ID code of the body name, or nothing if the name is not known, as bods2c_c.

name is a body name or a string that holds an integer, such as "399". Letter case and blanks around the name are ignored. Names from the kernel pool and from boddef have priority over the built-in names. nothing takes the place of the found flag of CSPICE.

Examples

julia> bods2c("Earth"), bods2c("-77"), bods2c("NO SUCH BODY")
(399, -77, nothing)

See also bodn2c, bodc2n.

Allspice.boddef — Function
boddef([ctx,] name, code) -> Nothing

Define name as a name of the body with the NAIF ID code, as boddef_c.

The pair has priority over the built-in names. A name or a code that the kernel pool defines (NAIF_BODY_NAME, NAIF_BODY_CODE) keeps the definition of the pool. The pair stays through furnsh, unload and kclear, as in CSPICE. A lookup ignores letter case and blanks around the name; bodc2n returns the name as given here.

Throws SpiceError(:badarg) if name is blank.

Examples

julia> ctx = SpiceContext();

julia> boddef(ctx, "My Probe", -999);

julia> bodn2c(ctx, "my probe"), bodc2n(ctx, -999)
(-999, "My Probe")
