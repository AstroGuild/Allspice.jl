Time

A call that needs the leap-second kernel and finds none throws a kind that is the short message of the CSPICE routine that the call ports: :kernelvarnotfound from deltet, :noleapseconds from str2et and utc2et, and :missingtimeinfo from et2utc, timout, unitim and the spacecraft clock calls such as sct2e.

Conversion

Allspice.deltet — Function
deltet([ctx,] epoch, eptype) -> Float64

Return the difference ET - UTC in seconds at epoch, as deltet_c.

eptype says how epoch is measured: "UTC" for UTC seconds past J2000, counted from 2000 JAN 01 12:00:00 UTC with 86400 seconds in every day (the result of tparse), or "ET" for seconds past J2000 TDB; letter case is ignored. A leap-second kernel must be loaded.

Throws SpiceError(:kernelvarnotfound) if no leap-second kernel is loaded and SpiceError(:badepochtype) if eptype is not "UTC" or "ET".

Examples

furnsh("naif0012.tls")
deltet(0.0, "ET")       # seconds, at J2000

See also unitim, str2et.

source
Allspice.utc2et — Function
utc2et([ctx,] s) -> Float64

Return the epoch of the UTC time string s in seconds past J2000 TDB, as utc2et_c.

str2et is the call for new code; this one keeps the behavior of the older CSPICE routine:

  • s has a form that str2et accepts, without a time zone, without A.M. or P.M. and without a time system other than UTC.
  • The defaults of timdef are not used: the string is UTC and the date is Gregorian. The year bound of tsetyr is used.
  • The components are not checked against their ranges, so 1996-02-30 is March 1, unless tparch has turned the check on for the context.

Throws SpiceError(:badtime) if s is not a time string of these forms or, with the check on, if a component is out of range, and SpiceError(:noleapseconds) if no leap-second kernel is loaded.

Allspice.str2et — Function
str2et([ctx,] s) -> Float64

Return the epoch of the time string s in seconds past J2000 TDB, as str2et_c.

A leap-second kernel must be loaded. The string forms of CSPICE are accepted:

FormExamples
ISO 8601"2025-03-01T12:00:00.5", "2025-060T12:00"
calendar, month name or number"1 MAR 2025 12:00:00", "March 1, 2025 3:00 PM", "3/1/2025"
day of year"2025-060 // 12:00"
Julian date"JD 2460736.0"

A string can also hold an era (B.C., A.D.), A.M. or P.M., a weekday, and a time zone (PDT, UTC-7:30) or a time system (UTC, TDB, TDT; not TT, as in CSPICE), but not a zone and a system together. A year can be abbreviated as '97 or given with two digits.

  • Without a zone and a system the string is UTC, or what timdef set for the context; a default system "TT" leaves it UTC, as in CSPICE.
  • The date is Gregorian, or of the calendar that timdef set for the context.
  • A year of two digits is in 1969 to 2068, or in the 100 years that tsetyr set for the context.
  • A UTC leap second 23:59:60 is accepted on a day that has one.
  • The components are checked against their ranges whatever tparch set, so "1996-02-30" throws.

Throws SpiceError(:badtime), with the reason in the message, if s is not a time string of these forms, and SpiceError(:noleapseconds) if no leap-second kernel is loaded.

Examples

furnsh("naif0012.tls")
et = str2et("2025-03-01T12:00:00")              # UTC
et = str2et("2025 MAR 01 12:00:00 TDB")         # the string names the time system
et = str2et("March 1, 2025 4:00 AM PST")        # the string names a time zone
timout(et, "YYYY-MM-DDTHR:MN:SC.### ::UTC ::RND")    # back to a string, rounded

See also timout, et2utc, utc2et, tparse.

Allspice.et2utc — Function
et2utc([ctx,] et, format, prec) -> String

Return the epoch et (seconds past J2000 TDB) as a UTC string, as et2utc_c.

A leap-second kernel must be loaded. format selects the form; letter case is ignored:

formatForm
"C"1986 APR 12 16:31:09.814
"D"1986-102 // 16:31:09.814
"J"JD 2446533.18834276
"ISOC"1986-04-12T16:31:09.814
"ISOD"1986-102T16:31:09.814

prec is the number of decimal places of the seconds, or of the Julian date; a value below 0 counts as 0, and the string has at most 13 decimal places of seconds and 7 of a Julian date, as in CSPICE. The fraction is rounded. The seconds are 60 inside a leap second. A year before 1000 has A.D. or B.C. in the formats C and D.

Throws SpiceError(:badformat) if format is not one of the five, SpiceError(:badtime) if the year is before 1 A.D. in an ISO format, and SpiceError(:missingtimeinfo) if no leap-second kernel is loaded.

Examples

furnsh("naif0012.tls")
et2utc(0.0, "ISOC", 3)      # UTC at the epoch J2000 TDB

See also timout, str2et.

Allspice.etcal — Function
etcal([ctx,] et) -> String

Return the calendar string of et (seconds past J2000 TDB) on the formal calendar, on which every day has 86400 seconds, as etcal_c.

The string has the form 1986 APR 12 16:31:09.814. It is a TDB date without leap seconds, and the call needs no kernel; ctx is accepted and not used. Use et2utc or timout for UTC. A year before 1000 has A.D. after it, and a year before 1 is written with B.C.. The seconds are rounded to milliseconds, but never up to 60. An epoch whose day number is outside the 32-bit integers gives Epoch before ... or Epoch after ... with the first or last date that can be written.

Examples

julia> etcal(0.0)
"2000 JAN 01 12:00:00.000"

julia> etcal(-1.0e11)
"1170 B.C. FEB 16 02:13:20.000"

Allspice.timout — Function
timout([ctx,] et, pictur) -> String

Return the epoch et (seconds past J2000 TDB) as a string in the form of the picture pictur, as timout_c.

A leap-second kernel must be loaded. The picture is copied to the result with each mark replaced by its component. Marks are case sensitive:

MarkComponent
YYYY, YRyear; last two digits of the year
MMmonth number
MON, Mon, monmonth name, three letters, in that letter case
MONTH, Month, monthmonth name, in that letter case
DD, DOYday of the month; day of the year
WKD, Wkd, wkdweekday, three letters
WEEKDAY, Weekday, weekdayweekday
HR, APhour 0 to 23; hour 1 to 12
MN, SCminute; second
AMPM, ampmA.M. or P.M., in that letter case
ERA, eraB.C. or A.D.
?ERA?, ?era?the era, blank from the year 1000 A.D.
JULIANDJulian date
SP2000, SP1950seconds past J2000; seconds past J1950
.#, #decimal point and decimals of the component to the left

These marks write nothing and select how the components are computed:

MarkSelects
::UTC, ::TDB, ::TDT, ::TTtime system
::UTC+h[:mm], ::UTC-h[:mm]time zone, such as ::UTC-8 or ::UTC+5:30
::GCAL, ::JCAL, ::MCALGregorian, Julian or mixed calendar
::RND, ::TRNCround or truncate the last component (default: truncate)

A picture without a system or zone mark is UTC, and one without a calendar mark is Gregorian, unless timdef changed the default of the context. The result has no trailing blanks. tpictr makes a picture from a sample string.

Throws SpiceError(:missingtimeinfo) if no leap-second kernel is loaded and SpiceError(:badformat) if pictur is the empty string.

Examples

furnsh("naif0012.tls")
et = str2et("2025-03-01T12:34:56.789")
timout(et, "YYYY-MM-DDTHR:MN:SC.### ::UTC")       # ISO form, UTC, truncated
timout(et, "Mon DD, YYYY AP:MN ampm ::UTC-8")     # 12 hour clock in a time zone
timout(et, "JULIAND.##### ::TDB ::RND")           # Julian date in TDB, rounded

See also et2utc, etcal, str2et.

Allspice.tparse — Function
tparse([ctx,] s) -> Float64

Return the seconds past J2000 of the time string s on a formal calendar, as tparse_c.

On the formal calendar every day has 86400 seconds: there are no leap seconds, and the call needs no kernel. The result is the count that etcal writes back, not an epoch of a uniform time scale; for a UTC string it is the "UTC" epoch of deltet. s has a form that str2et accepts, without a time zone, a time system, or A.M. and P.M..

A year of two digits follows tsetyr of the context: at start the year 69 is 1969 and the year 68 is 2068. The components are not checked against their ranges, so "1996-02-30" is March 1, unless tparch has turned the check on for the context.

Throws SpiceError(:badtime) if the string cannot be parsed or, with the check on, if a component is out of range; the message is the one that tparse_c returns in errmsg.

Examples

julia> tparse("2000-01-01T12:00:00")
0.0

julia> tparse("2 JAN 2000")
43200.0

Allspice.timdef — Function
timdef([ctx,] action, item, value="") -> String

Set or get a default of the time conversions of ctx, as timdef_c.

action is "SET" or "GET" and item is "CALENDAR", "SYSTEM" or "ZONE"; letter case is ignored. "GET" returns the default ("" if the item is not set). "SET" stores value and returns the stored form.

itemValuesAt start
"CALENDAR""GREGORIAN", "JULIAN", "MIXED" (Julian before 1582 OCT 15)"GREGORIAN"
"SYSTEM""UTC", "TDB", "TDT", "TT""UTC"
"ZONE""EST", "EDT", "CST", "CDT", "MST", "MDT", "PST", "PDT", "UTC+h[:mm]", "UTC-h[:mm]"""

A zone is stored as an offset, such as "UTC-8". A system clears the zone and a zone clears the system.

The defaults apply to str2et (the calendar, and the system or the zone for a string that names neither) and to timout for a picture that names no system, zone or calendar. They belong to the context; CSPICE keeps one set for the process.

Throws SpiceError(:badtimedefault) if the action, the item or the value is not one of the above; the defaults are then unchanged.

Examples

julia> ctx = SpiceContext();

julia> timdef(ctx, "GET", "SYSTEM")
"UTC"

julia> timdef(ctx, "SET", "ZONE", "PST")
"UTC-8"

julia> timdef(ctx, "GET", "SYSTEM")
""

Allspice.unitim — Function
unitim([ctx,] epoch, insys, outsys) -> Real

Return the epoch epoch of the uniform time scale insys, a scale without leap seconds, expressed in the scale outsys, as unitim_c.

ScaleEpoch is
"TAI"TAI seconds past J2000 TAI
"TDT", "TT"TDT seconds past J2000 TDT
"TDB", "ET"TDB seconds past J2000 TDB
"GPS"GPS seconds past J2000 GPS (TAI - 19 s)
"JDTDT"Julian date in TDT, days
"JDTDB", "JED"Julian date in TDB, days

Letter case is ignored. UTC is not a uniform scale: use str2et and et2utc for it. A leap-second kernel must be loaded; the call reads its constants for TDB - TDT and for TDT - TAI. The result has the number type of epoch * 1.0, so a dual-number epoch keeps its derivatives. The call does not allocate.

Throws SpiceError(:badtimetype) if a scale is not one of the above and SpiceError(:missingtimeinfo) if no leap-second kernel is loaded.

Examples

furnsh("naif0012.tls")
et = str2et("2025-03-01T12:00:00")
jd = unitim(et, "TDB", "JDTDB")     # Julian date, TDB
tt = unitim(et, "TDB", "TT")        # seconds past J2000, TT

See also deltet.

Allspice.tsetyr — Function
tsetyr([ctx,] year) -> Nothing

Set the first year of the 100 years that a year of two digits stands for, as tsetyr_c.

At start the value is 1969: the year 69 is 1969 and the year 68 is 2068. After tsetyr(ctx, 1980) the year 80 is 1980 and the year 79 is 2079. The value applies to str2et, utc2et and tparse on the context, and to the @ dates of the text kernels that the context loads afterwards (furnsh, ldpool, lmpool). A year that is not positive changes nothing, as in CSPICE. The value belongs to the context; CSPICE keeps one for the process.

Examples

julia> ctx = SpiceContext();

julia> etcal(tparse(ctx, "79 JAN 1"))
"1979 JAN 01 00:00:00.000"

julia> tsetyr(ctx, 1980)

julia> etcal(tparse(ctx, "79 JAN 1"))
"2079 JAN 01 00:00:00.000"

Allspice.tparch — Function
tparch([ctx,] type) -> Nothing

Turn the range check of the components of a time string on (type = "YES") or off (any other value), as tparch_c.

Letter case and blanks of type are ignored. At start the check is off: then tparse and utc2et accept "1996-02-30" as March 1 and a time of "24:00:00" as the next day. With the check on they throw for a month outside 1 to 12, a day outside its month or year, an hour, minute or second outside its range, or a fraction in a component that is not the last one. The setting applies to these two calls on the context and to the @ dates of the text kernels that the context loads afterwards (furnsh, ldpool, lmpool). The setting belongs to the context; CSPICE keeps one for the process.

Throws SpiceError(:emptystring) if type is empty.

Examples

julia> ctx = SpiceContext();

julia> etcal(tparse(ctx, "1996-02-30"))
"1996 MAR 01 00:00:00.000"

julia> tparch(ctx, "YES")

julia> try
           tparse(ctx, "1996-02-30")
       catch err
           err.kind
       end
:badtime

Return the Gregorian calendar date, and its day of year, of a date given in the Julian calendar, as jul2gr of SPICELIB (CSPICE has it without a _c wrapper).

Spacecraft clocks

Allspice.sct2e — Function
sct2e([ctx,] sc, sclkdp) -> Real

Return the epoch, in seconds past J2000 TDB, of the encoded spacecraft clock value sclkdp of the clock sc, as sct2e_c.

sc is the NAIF ID of the spacecraft. sclkdp is in ticks, the counts of the last field of the clock, from the start of the first partition; scencd makes it from a clock string. A partition is a span on which the clock counts without a reset or a jump. An SCLK kernel for sc must be loaded, and a leap-second kernel if the parallel time system of the clock, the time scale to which the kernel relates the ticks, is TDT (SCLK01_TIME_SYSTEM_<-sc> = 2). The result has the number type of sclkdp (Float64 for an integer), so a dual number keeps its derivative. The call does not allocate.

Throws SpiceError(:kernelvarnotfound) if no SCLK kernel for sc is loaded or its data are incomplete, and SpiceError(:notsupported) if the clock is not of type 1. Throws SpiceError(:valueoutofrange) if sclkdp is outside the range of the kernel and SpiceError(:missingtimeinfo) if a leap-second kernel is needed and not loaded.

Examples

furnsh("naif0012.tls")
furnsh("mission.tsc")                    # the SCLK kernel of the spacecraft -77
et = sct2e(-77, scencd(-77, "1/0123456789:123"))
et = scs2e(-77, "1/0123456789:123")      # the same in one call

See also sce2c, scs2e.

source
Allspice.sce2c — Function
sce2c([ctx,] sc, et) -> Real

Return the continuous encoded spacecraft clock value of the clock sc at et, as sce2c_c.

et is in seconds past J2000 TDB. The result is in ticks from the start of the first partition and can have a fraction, which makes it continuous; sce2t gives the discrete value, rounded to whole ticks. This is the form that ckgp takes. The result has the number type of et, and the call does not allocate.

Throws the errors of sct2e, with et in the place of sclkdp.

Allspice.scencd — Function
scencd([ctx,] sc, sclkch) -> Float64

Return the encoded spacecraft clock value of the clock string sclkch of the clock sc, as scencd_c.

sclkch has the form "partition/fields", such as "1/0123456789:123"; the partition number is optional. The result is in ticks from the start of the first partition. Without a partition number, the first partition that holds the count is taken.

Throws SpiceError:

  • :badpartnumber if the partition number cannot be read or is not the number of a partition;
  • :notinpart if the count is not inside the given partition;
  • :nopartition if no partition holds the count;
  • :invalidsclkstring if the fields cannot be read (see sctiks).

Also throws the SCLK kernel errors of sct2e.

See also scdecd, scs2e.

Allspice.sctiks — Function
sctiks([ctx,] sc, clkstr) -> Float64

Return the tick count of the clock string clkstr of the clock sc, as sctiks_c.

clkstr has no partition number. Its fields are given most significant first and are separated by ., :, -, , or blanks. Each field counts from its offset, the value of SCLK01_OFFSETS in the SCLK kernel (the value of the field when the count is zero). A blank field counts as its offset. The result is a count inside one partition, not an encoded clock value; see scencd.

Throws SpiceError(:invalidsclkstring) if the string is blank, has too many fields, has a field that is not a number, or has a field below its offset. Also throws the SCLK kernel errors of sct2e.

See also scfmt.

source
Allspice.scfmt — Function
scfmt([ctx,] sc, ticks) -> String

Return the clock string of the tick count ticks of the clock sc, without a partition number, as scfmt_c.

ticks is rounded to a whole number and split into the fields of the clock. Each field is written with leading zeros to the width of its largest value, with the output delimiter of the clock between the fields: the character ., :, -, , or blank that SCLK01_OUTPUT_DELIM_<-sc> selects with 1 to 5. This is the inverse of sctiks.

Throws SpiceError(:valueoutofrange) if ticks is negative. Also throws the SCLK kernel errors of sct2e.

Local time

Allspice.et2lst — Function
et2lst([ctx,] et, body, lon, type) -> (hr, mn, sc, time, ampm)

Return the local solar time at et for the longitude lon on the body with ID body, as et2lst_c.

  • et: seconds past J2000 TDB, a plain real number (not a ForwardDiff.Dual).
  • lon: longitude in radians.
  • type: "PLANETOCENTRIC" (lon positive east) or "PLANETOGRAPHIC" (lon with the sense of recpgr for the body: positive west for a prograde body such as Mars), in any letter case.

hr, mn and sc are the integer hour, minute and second on a 24 hour clock. time is the string HH:MM:SS, and ampm is the string HH:MM:SS A.M. or HH:MM:SS P.M. on a 12 hour clock.

The local solar time is the angle between the meridian of lon and the meridian of the Sun, with 12:00:00 at the sub-solar meridian and 24 "hours" in one rotation; an "hour" is not 3600 s. The position of the Sun has the correction "LT+S" and is in the body-fixed frame of cidfrm. The sign of the second value of BODY<body>_PM gives the direction of the rotation. For the Sun (body = 10) the result is always 12:00:00. The call needs SPK data for the body and the Sun and PCK data for the body.

Throws SpiceError, with the checks in this order, as in CSPICE after the first:

  • :badarg if et is a ForwardDiff.Dual;
  • :invalidoption, for "PLANETOGRAPHIC", if BODY<body>_PGR_POSITIVE_LON is not EAST or WEST;
  • :missingdata, for "PLANETOGRAPHIC", if BODY<body>_PGR_POSITIVE_LON and BODY<body>_PM are both absent and the body is not the Earth;
  • :unknownsystem if type is not one of the two;
  • :cantfindframe if the body has no body-fixed frame;
  • the kinds of spkezr;
  • :cantgetrotationtype if BODY<body>_PM is absent or is not a numeric variable of two or more values.

Examples

furnsh("naif0012.tls"); furnsh("pck00011.tpc"); furnsh("de440s.bsp")
et = str2et("2025-03-01T12:00:00")
hr, mn, sc, time, ampm = et2lst(et, 399, deg2rad(-118.0), "PLANETOCENTRIC")

Allspice.lspcn — Function
lspcn([ctx,] body, et, abcorr) -> Float64

Return the planetocentric longitude of the Sun (Ls) for body at et, in radians in [0, 2pi), as lspcn_c.

Ls is the season angle of the body: 0 at its spring equinox of the north, pi/2 at the summer solstice of the north. It is the right ascension of the Sun as seen from the body, in this frame:

  • the Z axis is the orbital angular momentum of the body about the Sun;
  • the X axis is the cross product of the north pole of the body and the Z axis.

body is a name or a NAIF ID, et is in seconds past J2000 TDB, and abcorr is as for spkezr. The call needs PCK data for the pole and SPK data for the body and the Sun.

Throws SpiceError(:dependentvectors) if the pole is parallel to the orbital angular momentum, and the errors of spkezr and tipbod.

Examples

furnsh("naif0012.tls"); furnsh("pck00011.tpc"); furnsh("de440s.bsp")
ls = rad2deg(lspcn("EARTH", str2et("2025-03-01"), "LT+S"))    # degrees
